# 匹配引擎设计

## 目标

在**真实、安全、公平**的前提下，为每个用户每天产出 3–5 个「大概率互相心动」的候选人，并给出可解释的匹配报告。

## 硬过滤（一票否决，全部通过才进入打分）

| 规则 | 说明 |
|---|---|
| 自我排除 | 不推荐自己 |
| 取向互洽 | 双方取向互相满足（见 matcher.orientationCompatible） |
| 年龄区间 | 由用户自设 minAge/maxAge |
| 校区距离意愿 | 用户自选：同校区 / 同城跨校区 / 接受异地 |
| 吸烟偏好 | acceptSmoker=false 时过滤吸烟者 |
| 同院系回避 | 避免熟人尴尬（默认开启，可配置） |
| 曝光配额 | 每人每天被推荐次数上限（默认 50），防头部通吃 |
| 状态过滤 | 仅推荐已验证、未隐藏、未脱单、未注销的用户 |

## 软打分

```
score = 0.60 × 价值观相似度
      + 0.25 × 兴趣重合度
      + 0.15 × 活跃度
      − 距离惩罚
```

- **价值观相似度**：双方问卷向量（5 维，L2 归一）的余弦相似度；
- **兴趣重合度**：兴趣标签集合的 Jaccard 系数；
- **活跃度**：近 30 天活跃天数 / 30（骨架阶段暂为常数 30，接入行为日志后启用真实值）；
- **距离惩罚**：同校区 0；同城跨校区 −0.05；跨城市 −0.15。

## 匹配报告（可解释性）

- 共同兴趣：双方标签交集（最多展示 3 个）；
- 共同价值观维度：双方向量分量同为正的维度按乘积取 Top2，映射为中文标签（消费观/婚恋观/家庭观/职业规划/相处模式）；
- 前端展示：「为什么是 TA：共同兴趣 篮球；你们在 消费观、职业规划 上很合拍」。

## 公平性约束

1. 每日曝光配额（candidate 视角），避免 5% 头部用户占据 80% 曝光；
2. 同一候选人 7 天内不重复推荐给同一用户（待实现：由 recommendations 历史判断）；
3. 每日派单幂等：同一天多次触发生成只返回已生成数量。

## 冷启动策略

- 新用户前 3 天：仅靠问卷静态打分（本引擎即是静态打分）；
- 数据积累后（>1 万用户、>10 万次决策）：引入 learning-to-rank，用「心动/忽略/聊天时长/见面反馈」作为标签训练排序模型，并保留当前打分作为 baseline。

## 评估计划

- 离线：历史推荐上的 AUC / NDCG；
- 在线：互相心动率、心动→聊天转化率、匹配后 7 日留存；
- 人工：每周抽 50 份推荐结果人工评分，防止算法走偏。

## 代码位置

- 纯函数引擎：`apps/server/src/modules/matching/matcher.ts`（含单元测试 `matcher.spec.ts`）
- 编排层：`apps/server/src/modules/matching/matching.service.ts`
- 共享基础：`packages/shared`（八校区常量、距离档位、问卷向量计算）
